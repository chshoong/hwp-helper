# hwp-helper 플러그인 설계

- 작성일: 2026-10-06
- 상태: 사용자 검토 대기

## 1. 목적

Claude에게 한글(HWP/HWPX) 문서 작성을 맡길 때 생기는 문제를 해결하는 Claude 플러그인을 만든다.
대상 문서는 국가연구 보고서, 기관 양식(월간보고서 등), 공문서·개조식 보고서, 학술 논문형 보고서다.

해결할 문제:

1. 수식·표·그림의 서식이 기존 문서와 맞지 않는다.
2. 한글에서 열면 깨지거나 열리지 않는다.
3. 양식이 어색하다(간격·기호 위계·정렬이 사람이 만든 문서와 다르다).
4. 글꼴이 맞지 않는다(함초롬바탕 등 지정 글꼴이 빠지거나 바뀐다).

### 성공 기준

- 결과물을 한글에서 열었을 때 오류·경고 없이 열리고, 사람이 같은 양식으로 만든 문서와 구별되지 않는다.
- 글꼴·줄간격·표 테두리·캡션 모양이 양식(또는 프리셋)과 동일하다.
- 수식은 한글 수식 개체로 들어가고, 한글에서 편집 가능하다.
- 코딩을 모르는 사용자도 말로 요청해서 완성 파일을 받는다.

## 2. 확정된 요구사항

| 항목 | 결정 |
|---|---|
| 실행 환경 | Claude Code(Windows, 한글 설치)에서는 강력 모드, claude.ai 웹·Mac·클라우드에서는 기본 모드. 기능은 자동 감지로 갈림 |
| 서식 출처 | 기관 양식 파일이 있으면 그것을 따른다. 없으면 프리셋 4종 중 선택 |
| 프리셋 | 국가R&D 보고서형, 공문서·개조식형, 학술 논문형, 월간·진도 보고형 |
| 내용 입력 | 대화, 분석 결과 파일(png·csv·xlsx·ipynb), 기존 문서(md·docx·pdf·tex), 이전 한글 보고서 |
| 출력 | .hwpx 기본, 요청 시 .hwp(한글 필요), PDF 미리보기(한글 필요) |
| 배포 | GitHub 저장소 = Claude Code 플러그인 마켓플레이스. claude.ai용 스킬 zip 별도 제공 |

## 3. 핵심 원칙: 견본 복제

> Claude는 **내용**만 만든다. **서식**은 견본에서만 가져온다.

- 엔진은 서식을 새로 정의하지 않는다. 모든 문단·표·그림·수식은 양식/프리셋 안의 **견본 요소를 복제**한 뒤 내용만 교체한다.
- 프리셋도 한글에서 실제로 만든 .hwpx 파일이다(코드로 생성한 서식이 아니다).
- Claude는 XML을 직접 편집하지 않고 **보고서 마크다운**(5장)을 작성한다. 엔진이 이것을 HWPX로 바꾼다.
- 한글 프로그램이 있으면 마지막에 한글로 열어 저장(줄배치 재계산)·검증·변환한다.

## 4. 사용자 흐름

### 4.1 진입

- 자연어로 시작: "한글로 보고서 써줘", "이 양식 채워줘", "월간보고서 만들어줘", "이 hwp 검토해줘".
- 단축 명령: `/hwp-write`(새로 작성), `/hwp-fill`(양식 채우기), `/hwp-review`(검토), `/hwp-convert`(hwp↔hwpx↔pdf).

### 4.2 시작 질문 (최대 3개, 객관식, 이미 답한 것은 묻지 않음)

1. 양식 파일이 있나요? → 파일 지정(.hwp도 자동 변환) / 없음 → 프리셋 선택
2. 내용은 어디서? (복수 선택) 대화로 설명 / 파일·폴더 지정 / 이전 보고서 이어쓰기
3. 결과 형식? .hwpx / .hwp / 둘 다 + PDF 미리보기 (한글 없는 환경에서는 .hwpx만 제시)

### 4.3 작업 단계

1. **분석**: 양식이면 "채울 칸 목록", 새 작성이면 "목차 초안"과 견본 카탈로그 요약을 보여준다.
2. **확인**: 사용자가 칸 배치·목차를 승인한다(한 번만).
3. **작성**: Claude가 보고서 마크다운을 쓰고 엔진이 렌더링한다. 긴 보고서는 장 단위로 진행한다.
4. **검증**: `validate` + `review`. 한글이 있으면 실제로 열어 PDF·쪽 이미지를 만들고 Claude가 눈으로 확인한다.
5. **전달**: 결과 파일, 쪽 미리보기(가능 시), "확인 필요" 목록(날짜 의심, 출처 없는 수치, 빈 칸 등).

### 4.4 사용자 친화 규칙

- 원본을 덮어쓰지 않는다. 결과는 `<원본명>_작성.hwpx`, 이후 수정은 `_작성2` 식으로 새 파일.
- 부분 수정 지원: "3장 2절만 다시", "표 2에 행 추가". 대상 외 부분은 바이트 수준으로 보존한다.
- 오류는 쉬운 말로 보고한다: "표 3의 2행 칸 수가 맞지 않아 자동으로 맞췄어요."
- 기본 모드에서는 "미리보기 없이 구조 검증만 했어요. 한글에서 한 번 열어 확인해 주세요."라고 알린다.

## 5. 보고서 마크다운 (Claude ↔ 엔진 인터페이스)

Claude가 작성하는 중간 형식. 사람이 읽을 수 있고, `reader`가 hwpx를 같은 형식으로 되돌릴 수 있다.

| 문법 | 의미(역할) |
|---|---|
| `# 제1장 서론` | `h1` 장 |
| `## 1. 연구 배경` | `h2` 절 |
| `### 1) 필요성` | `h3` 항 |
| `#### 가. 세부` | `h4` |
| `□ 문장` / `○ 문장` / `- 문장` / `· 문장` | `bullet1`~`bullet4` 개조식 위계 |
| 일반 문단 | `body` |
| `**굵게**`, `*기울임*`, `[[색:파랑]]텍스트[[/색]]` | 인라인 서식(견본의 글자모양을 바탕으로 해당 속성만 바꾼 변형) |
| 파이프 표 + 직전 줄 `표: 캡션` | `table` + `caption`. 병합은 `^^`(위와 병합), `<<`(왼쪽과 병합) |
| `![캡션](경로.png){width=80%}` | `figure` + `caption` |
| `$$ LaTeX $$` / 인라인 `$ LaTeX $` | 한글 수식(문단 수식은 번호 자동, `{#eq:label}`로 참조) |
| `[@fig:label]`, `[@tbl:label]`, `[@eq:label]` | 상호 참조 → "그림 1-2" 식 번호로 치환 |
| `---쪽---` | 쪽 나눔 |
| `<!-- 메모 -->` | 렌더링하지 않음 |

양식 채우기는 별도 YAML/JSON 대신 같은 마크다운을 칸 단위로 쓴다(7장).

## 6. 엔진 `hwpxkit` (Python 3.10+, 의존성: lxml, Pillow)

각 모듈은 단독으로 테스트 가능하고, 위 모듈은 아래 모듈만 사용한다.

| 모듈 | 책임 | 주요 인터페이스 |
|---|---|---|
| `package` | hwpx zip 읽기·쓰기. `mimetype`을 첫 항목·무압축으로 저장, `content.hpf` manifest와 `BinData` 관리, 바꾸지 않은 파트는 원본 바이트 유지 | `Package.open(path)`, `.save(path)`, `.add_bin(data, ext) -> id` |
| `header` | `header.xml`의 fontface·charPr·paraPr·borderFill·style ID 레지스트리. 변형 서식이 필요하면 기존 항목을 복제해 속성만 바꾸고, 동일 항목이 있으면 재사용 | `get_charpr(id)`, `derive_charpr(base_id, **changes) -> id` |
| `samples` | 견본 카탈로그. 역할(`h1`…`body`, `bullet1-4`, `caption`, `table.head`, `table.body`, `figure`, `equation`, `cell:<이름>`) → 견본 요소. 프리셋은 `preset.json`으로 명시, 사용자 양식은 패턴·서식으로 추정 후 사용자 확인 | `Catalog.from_preset(dir)`, `Catalog.infer(pkg) -> (catalog, uncertain_roles)` |
| `layout` | 쪽 설정(secPr)에서 본문 폭 계산, HWPUNIT(1/7200 inch) 변환, 그림 크기·표 열 너비 계산 | `text_width(pkg)`, `fit_image(w,h,max_ratio)` |
| `render` | 보고서 마크다운 파싱 → 견본 복제로 요소 삽입. 번호(그림·표·수식) 매기기, 상호 참조 치환, `linesegarray` 제거 | `render(md, catalog, pkg, at=None)` |
| `form` | 양식 칸 탐색(행 머리 × 열 머리, 또는 칸 안의 안내 문구)과 채우기. 칸의 기존 문단·글자 서식(예: 파란 글씨) 유지, 반복 행 복제 | `list_fields(pkg)`, `fill(pkg, {field: md})` |
| `equation` | LaTeX ↔ 한글 수식 스크립트 변환. 지원 범위 밖 구문은 오류 목록으로 보고 | `latex_to_hwp(s)`, `hwp_to_latex(s)` |
| `reader` | hwpx → 보고서 마크다운(역할 주석 포함). 이어쓰기·부분 수정·검토의 기반 | `to_markdown(pkg) -> str` |
| `validate` | 깨짐 방지: XML 정합성, 모든 IDRef가 header에 존재, 표 행·열·병합 합 일치, 글꼴이 fontface에 정의, manifest와 BinData 일치, mimetype 규칙 | `validate(pkg) -> [Issue]` |
| `review` | 내용 점검: 날짜·요일 일치, 연도 의심(보고 대상 기간과 불일치), 번호 연속성, 캡션·참조 일치, 빈 칸·안내 문구 잔존, 견본 외 서식 사용 | `review(pkg) -> [Finding]` |
| `bridge` | 한글 연동(Windows+한글일 때만). PowerShell로 `HWPFrame.HwpObject` COM 호출(pywin32 불필요). hwp↔hwpx, PDF, 쪽 PNG, 열기 검사, 열고 다시 저장(줄배치 재계산), 차례·필드 갱신 | `available() -> bool`, `convert(src, fmt)`, `snapshot(path) -> [png]` |
| `cli` | 스킬·명령이 호출하는 단일 진입점 `python -m hwpxkit <cmd>` (`inspect`, `fields`, `render`, `fill`, `read`, `validate`, `review`, `convert`, `preview`) | JSON 출력 옵션 `--json` |

엔진에 포함하지 않는 것: docx·pdf·tex·csv·ipynb 읽기. Claude가 기존 도구로 읽고 보고서 마크다운으로 정리한다(수식은 LaTeX 그대로 두면 `equation`이 변환).

## 7. 양식 채우기 상세

- `fields`가 양식의 칸 목록을 사람 말로 보여준다. 예: `[표2] 가상 과제 1… × 금월 추진실적 (비어 있음)`.
- 칸 지정은 표 번호 + 행 머리 + 열 머리, 또는 안내 문구(예: "상세 추진 내용")로 한다.
- 칸 안 서식: 칸에 있던 문단·글자 서식을 견본으로 쓴다. 칸 안에 `□`/`-` 문단 견본이 있으면 그것을 쓰고, 없으면 같은 문서의 다른 칸에서 찾는다.
- 반복 행(예: 별첨의 항목 행)은 마지막 데이터 행을 복제해 늘리고 병합 구조를 유지한다.
- 파생 칸: 다른 칸에서 나오는 값(예: 별첨 "구분" = 실적 칸의 `-` 항목)은 Claude가 채우기 계획에서 명시하고 사용자에게 보여준다.
- 표지·머리말의 날짜·회차는 `review`가 보고 대상 기간과 대조한다.

## 8. 각 문제에 대한 대책

| 문제 | 대책 |
|---|---|
| 글꼴 | fontface는 견본 것만 사용. 함초롬바탕 등 HCR 글꼴은 프리셋에 정의. `validate`가 미정의 글꼴 참조를 차단. 기본 모드 PDF 미리보기는 하지 않음 |
| 표 | 견본 표 복제(머리행·본문행 서식 분리), 열 너비 합 = 본문 폭(또는 견본 표 폭), 셀 여백·테두리는 견본 borderFill, 긴 표는 견본의 쪽 나눔 설정 따름, 병합 합 검증 |
| 그림 | Pillow로 PNG 변환(BMP 등 대용량 압축), 원본 비율 유지, 본문 폭 × width% 이내, 글자처럼 취급 배치 + 캡션 견본, 번호 자동 |
| 수식 | LaTeX → 한글 수식 스크립트, 견본 수식 개체 복제(글꼴·크기), 번호는 견본의 수식 번호 방식(오른쪽 정렬) 따름 |
| 깨짐 | `linesegarray` 제거, ID·manifest·mimetype 검증, 한글 있으면 열기 검사 후 다시 저장 |
| 어색한 양식 | 역할별 견본만 사용, 문체 가이드(개조식 명사형 종결 등)를 스킬 참고 문서로 제공, `review`로 일관성 점검 |

## 9. 프리셋

- `presets/<이름>/template.hwpx`: 한글에서 만든 견본 문서. 각 역할의 견본 문단·표·그림·수식이 한 번 이상 들어 있다.
- `presets/<이름>/preset.json`: 역할 → 견본 위치, 번호 방식(예: `그림 {장}-{n}`), 문체 규칙.
- 4종: `rnd-report`(국가R&D, 함초롬바탕 본문), `gov-brief`(공문서·개조식, 휴먼명조/맑은고딕 계열), `paper`(학술 논문형), `progress`(월간·진도 보고형).
- 프리셋은 `bridge`로 한글 자동화를 써서 제작하고, 실제 기관 보고서의 **서식만** 참고한다(내용은 넣지 않는다).

## 10. 스킬·플러그인 구성

```
hwp-helper/
├─ .claude-plugin/plugin.json, marketplace.json
├─ skills/hwp-helper/SKILL.md          흐름, 시작 질문, 규칙
├─ skills/hwp-helper/reference/        markdown-syntax.md, equations.md, style-guide.md, troubleshooting.md
├─ commands/hwp-write.md, hwp-fill.md, hwp-review.md, hwp-convert.md
├─ hwpxkit/                             엔진
├─ presets/                             4종
├─ tests/                               가상 문서 기반 테스트
└─ dist/hwp-helper-skill.zip           claude.ai 업로드용(빌드 산출물)
```

- 스킬은 첫 실행 때 의존성(lxml, Pillow)을 확인하고, 없으면 설치 명령을 안내하거나 대신 실행한다.
- 스킬은 `bridge.available()`로 모드를 판단해 사용자에게 한 줄로 알린다.

## 11. 오류 처리

- `validate`가 오류를 찾으면 저장하지 않는다. 자동 수정 가능한 것(열 너비 합, 고아 ID 등)은 고치고 무엇을 고쳤는지 보고한다.
- 수식 변환 실패: 해당 수식을 원문 LaTeX 텍스트로 넣고 강조 표시한 뒤 "확인 필요" 목록에 올린다. 문서 전체를 실패시키지 않는다.
- 사용자 양식에서 역할 추정이 불확실하면 추정 결과를 보여주고 확인받는다.
- 한글 COM 호출이 시간 초과되거나 보안 대화상자에 막히면 기본 모드로 내려가고 그 사실을 알린다.

## 12. 테스트

- 단위 테스트: 모듈별(pytest). 가상 문서 fixture만 저장소에 넣는다.
- 왕복 테스트: `reader → render`로 다시 만든 문서가 원본과 같은 구조·서식 ID를 갖는지.
- 수식 말뭉치: LaTeX ↔ 한글 수식 왕복. 사용자 최종보고서의 수식 269개는 **로컬 전용** 정답 자료로 사용.
- 한글 통합 테스트(로컬, 한글 있을 때만): 결과물을 COM으로 열기 → 오류 없음, PDF 생성, 쪽 수 확인.
- 개인정보: 사용자가 준 보고서는 `private/`(gitignore)에만 두고 커밋하지 않는다.

## 13. 먼저 확인할 위험 (구현 첫 단계 스파이크)

1. 수식 개체의 크기 값이 부정확할 때 한글이 열면서 다시 계산하는가. 아니면 크기 추정 로직 또는 `bridge`로 재저장이 필수가 된다.
2. `linesegarray`를 제거한 문서를 한글 외 뷰어(한컴독스, 폴라리스 등)에서 열었을 때 정상인가.
3. 표 셀 크기 값(cellSz)이 내용보다 작을 때 한글이 자동으로 늘리는가.
4. 사용자 양식의 실제 구조(월간보고서 표 2·3)에서 칸 탐색 규칙이 동작하는가.

결과에 따라 6장·8장을 수정한다.
