# 열린 한글 창 실시간 연동 (live) 설계

## 1. 목적

사용자가 한글(한컴오피스)에서 열어 둔 문서를 Claude가 그 자리에서 읽고 고친다. 저장하지 않은 수정까지 포함해 화면 속 문서를 그대로 다루고, 서식은 문서의 견본을 복제해 유지한다.

## 2. 배경

- 플러그인 없이도 최신 Claude는 한글이 설치된 PC에서 한글 자동화를 스스로 찾아 파일 단위 작업(양식 채우기, 보고서 작성)을 꽤 잘 해낸다(2026-10-07 비교 실험). 겉모양 차이는 작았고, 차이는 한글 캡션·자동 번호, 쪽 나눔 설정, 검토 절차 같은 속 구조에 있었다.
- 그래서 플러그인 없이는 하기 어려운 일, 즉 **사용자가 작업 중인 한글 창과 Claude가 실시간으로 함께 편집하는 경험**에 집중한다.
- 한글을 Claude 앱 안에 띄우는 것은 불가능하다. 앱 안 편집 페이지(아티팩트)는 다음 하위 프로젝트로 따로 설계한다(이 문서 범위 밖).

## 3. 검증된 사실 (실험, 한글 2024 13.0.0.564)

| 확인 | 방법 | 결과 |
|---|---|---|
| 사용자가 연 한글 창에 연결 | `GetActiveObject("HWPFrame.HwpObject")`는 실패(MK_E_UNAVAILABLE). 실행 중 개체 목록(ROT)에 `!HwpObject.130.1` 이름으로 등록돼 있어 그 개체를 꺼냄 | 성공. 새 한글이 뜨지 않음. `Path`, `XHwpDocuments.Count` 읽힘 |
| 선택 영역 읽기 | `SelectionMode`, `GetTextFile("TEXT", "saveblock")` | 성공(사용자가 직접 드래그한 선택 포함) |
| 선택 영역 바꾸기 | `HAction InsertText` (선택 상태에서) | 성공. 글자 모양(휴먼명조 15pt) 유지 |
| 되돌리기 | `Run("Undo")`, `Run("Redo")` / 사용자 Ctrl+Z | 성공 |
| 창을 바꾸지 않고 내보내기 | `GetTextFile("HWP", "")` → base64 → .hwp 파일 → 별도 한글로 .hwpx 변환 | 성공. 저장 안 한 수정 포함, 창의 `Path`·`IsModified` 그대로 |
| 엔진 조각 끼워 넣기 | 내보낸 문서로 견본을 배워 조각(.hwpx) 생성 → `HAction InsertFile`(KeepSection=0, KeepCharshape·KeepParashape·KeepStyle=1) | 성공. 글머리·글꼴 유지, 새 표 캡션에 한글 자동 번호가 이어서 붙음([표 2]) |
| 주의 | `SaveAs`를 부르면 창의 문서 경로가 바뀜 | 실제 기능에서는 SaveAs를 쓰지 않음 |

## 4. 구성

- `hwpxkit/live.py` — 열린 한글과의 연결 담당. 파이썬 쪽 인터페이스.
- `hwpxkit/live_hwp.ps1` — 실제 한글 자동화(ROT 연결, 선택·커서 정보, 글 바꾸기, 조각 끼워 넣기, 내보내기, 메모 달기, 찾기·범위 선택). 기존 `bridge_hwp.ps1`처럼 JSON으로 결과를 돌려준다.
- 기존 엔진 재활용: 내보낸 문서로 `samples.infer` → `render`로 조각 생성, `review`로 검토, `reader`로 읽기.
- CLI `hwpx.py live <동작>` — 스킬이 부른다.

### CLI

| 명령 | 하는 일 |
|---|---|
| `live status [--json]` | 열린 한글 창·문서 목록, 현재 문서 경로, 수정 여부, 선택 여부 |
| `live selection [--json]` | 선택한 글, 앞뒤 문단(문맥), 위치 종류(본문/표 칸/기타), 선택이 걸친 문단 수 |
| `live replace <내용.md>` | 선택 영역을 바꾼다. 한 문단 안이면 글만 바꿔 글자 모양 유지(InsertText), 여러 문단이면 엔진 조각으로 바꿔 글머리 단계 유지 |
| `live insert <내용.md>` | 커서 자리에 엔진 조각(표·그림·수식·글머리 묶음)을 끼워 넣는다 |
| `live export <결과.hwpx>` | 화면 속 문서를 파일로 내보낸다(창은 그대로) |
| `live review [--memo]` | 화면 속 문서를 검토한다. `--memo`면 지적 사항을 해당 문단에 한글 메모로 단다 |
| `live section <제목 글> <내용.md>` | 그 제목부터 같은 단계의 다음 제목 앞까지를 다시 쓴 내용으로 바꾼다("2장만 다시 써줘") |

여러 창이 열려 있으면 `--doc <문서 이름 일부>`로 고른다. 모든 명령은 저장하지 않는다.

## 5. 기능 흐름 (스킬)

1. **고른 부분 다듬기·줄이기·늘리기·개조식으로**: `live selection`으로 선택과 문맥을 읽고 → 바꿀 글과 새 글을 대화에 보여 주고 → `live replace`. 한두 문장은 바로, 큰 범위는 확인 후.
2. **커서 자리에 넣기**: 내용 마크다운을 쓰고 → `live insert`. 캡션 번호는 한글 자동 번호(장별 형식이면 글자 번호).
3. **열린 문서 검토**: `live review --memo` → 지적 사항을 대화에도 요약.
4. **장 다시 쓰기·번호 다시 매기기**: `live section` 또는 찾아 바꾸기. 번호가 한글 자동 번호면 한글이 맞춘다.

## 6. 안전장치

- 고치기 전에 대상 창·문서 이름과 수정 여부를 알려 준다. 창이 여러 개면 묻는다.
- 바꾸기 전에 "바꿀 글 → 새 글"을 보여 준다. 장 단위 등 큰 변경은 확인받는다.
- 큰 변경 전에는 화면 속 문서를 임시 사본으로 내보내 둔다(되살리기용). 한 요청은 한글 되돌리기로 취소할 수 있게 한다.
- 저장·다른 이름으로 저장은 절대 하지 않는다.
- 다듬기·줄이기에서 원문에 없는 수치·사실은 넣지 않는다. 필요하면 `( )`로 비우고 알린다.

## 7. 오류 처리

| 상황 | 알림 |
|---|---|
| 한글이 안 열려 있음 | "한글에서 문서를 연 뒤 다시 말씀해 주세요." |
| 선택이 필요한데 없음 | "한글에서 고칠 부분을 드래그해 주세요." |
| 지원하지 않는 위치(머리말·각주·글상자 등) | 지원 범위를 알리고 할 수 있는 것만 한다. 표 칸 안 글 바꾸기는 지원 |
| 한글이 응답 없음(확인 창) | "한글에 떠 있는 창을 닫아 주세요." (시간 제한 후) |
| 한글이 없는 환경 | "이 기능은 한글이 설치된 Windows에서만 돼요." 파일 기반 기능으로 안내 |

## 8. 확인할 것 (계획의 첫 작업에서 검증)

- 한글 메모를 특정 문단에 다는 자동화 명령(메모 넣기 동작과 매개변수).
- 선택 위치 종류(표 칸 안 여부) 판별 방법, 여러 문단 선택의 시작·끝 위치(`GetSelectedPos`).
- 한글 창이 여러 개(여러 프로세스 또는 한 프로세스 여러 창)일 때 ROT 항목과 문서 대응.
- `live section`의 범위 선택(제목 찾기 → 다음 같은 단계 제목 앞까지 선택) 방법.

## 9. 테스트

- 자동(한글 없이): `live.py`의 명령 조립·결과 해석·오류 문구를 가짜 실행기로 시험. 조각 생성, 메모 위치 계산, 범위 계산은 파일로 시험.
- 한글 실제 테스트(`hangul` 표시, 한글 있는 PC만): 시험용 창을 띄워 연결 → 선택 읽기 → 바꾸기 → 되돌리기, 조각 끼워 넣기, 메모 달기, 내보내기 후 창 경로·수정 상태 불변 확인. 사용자 창은 건드리지 않는다.
- 마지막에 사용자와 실제 창에서 한 번 시험한다.

## 10. 범위 밖

- 앱 안 한글 문서 편집 페이지(아티팩트): 다음 하위 프로젝트.
- 목차·상호 참조(B), 검토·협업(C의 나머지), 반복 업무(D): 이후 하위 프로젝트.
