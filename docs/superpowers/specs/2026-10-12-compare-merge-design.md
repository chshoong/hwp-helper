# 이전 판 비교(compare)와 여러 사람 의견 합치기(merge) 설계

## 1. 목적

- **이전 판 비교:** 두 판의 보고서를 문단·표 칸 단위로 비교해 바뀐 곳(추가·삭제·수정)을 장별로 보여 주고, 원하면 새 판 사본에 "[바뀜]" 한글 메모를 단다.
- **의견 합치기:** 원본과 여러 사람이 돌려준 파일(한글 메모를 단 것, 본문을 직접 고친 것)을 받아, 원본 사본 하나에 모든 의견을 이름 붙인 한글 메모로 모은다(의견 모음본). 사용자가 고른 수정만 본문에 반영한다. 따로 받은 글(카톡·메일)은 Claude가 문단을 찾아 같은 모음본에 메모로 더한다.

## 2. 결정 (2026-10-12 사용자와 정함)

- 의견 형태: 한글 메모, 직접 고친 파일, 따로 받은 글.
- 합치는 방식: 의견 모음본을 만들고, 반영은 사용자가 고른 것만(자동 반영 없음).
- 메모는 숨은 한글의 메모 기능(InsertFieldMemo)으로 단다(live에서 검증). 한글이 없으면 대화의 표로만 정리한다.

## 3. 비교 엔진 (`hwpxkit/compare.py`)

### 단위

`units(pkg) -> list[Unit]` — 첫 구역의 문서 순서대로:

- 최상위 문단마다 하나: `Unit(key=("p", i), text, where)`.
- 표의 칸 문단마다 하나: `Unit(key=("c", i, t, r, c, k), text, where)`. i는 표를 담은 최상위 문단 번호, t는 문서 안 표 번호(form.cells와 같음), r·c는 칸 주소, k는 칸 안 문단 순서.
- `text`는 공백을 하나로 줄인 글(메모 내용·필드 안 글 제외). 빈 글 단위는 비교에서 뺀다.
- `where`는 그 단위 앞 가장 가까운 h1~h2 제목(없으면 "(앞부분)")과, 칸이면 " · 표{t} {r+1}행 {c+1}열".

### 비교

`diff(old, new) -> list[Change]` — `difflib.SequenceMatcher`로 두 단위 목록의 글을 맞춘다(autojunk=False).

- `equal`: 바뀌지 않음.
- `replace`: 짝지은 단위끼리 `SequenceMatcher(None, a, b).ratio() >= 0.5`이면 수정(`edit`), 아니면 삭제+추가. 남는 쪽은 삭제·추가.
- `delete` → `{"kind": "del", "old": …, "where": old.where}`, `insert` → `{"kind": "add", "new": …, "where": new.where, "after": 바로 앞 같은 단위의 새 판 글}`.
- 수정은 `{"kind": "edit", "old", "new", "where", "old_key", "new_key"}`.
- 서식만 다른 것은 같은 글이라 나오지 않는다.

## 4. 메모 읽기

`memos(pkg) -> list[dict]` — 모든 구역의 `fieldBegin type="MEMO"`마다 `{"text": 메모 글, "anchor": 메모가 붙은 본문 글(fieldBegin~fieldEnd 사이 hp:t), "where": 단위 where}`. 메모 글은 `form._memo_text`, 붙은 글은 `form._take_memos`와 같은 방식으로 얻는다(원본을 고치지 않게 읽기만).

합치기에서 "새 메모" = 의견 파일의 메모 가운데 (text, anchor)가 원본 메모 목록에 없는 것.

## 5. 메모 달기 (한글)

- `bridge_hwp.ps1` 동작 `memos`: `-Format`에 JSON 파일 경로를 받는다. `[{"anchor": 글, "n": 순번(1부터), "text": 메모 글}]`. 숨은 한글로 Src를 열고, 메모마다 처음으로 가서 `RepeatFind`로 anchor를 n번째까지 찾은 뒤 `InsertFieldMemo` → 메모 칸이 열렸는지(List 바뀜) 확인 → `InsertText` → `CloseEx`. 못 찾거나 열리지 않으면 missed에 넣는다. 끝나면 Dst로 HWPX 저장. 결과 `{placed, missed: [순서 번호]}`.
- anchor 못 찾은 메모는 엔진이 다시 `{"anchor": 첫 본문 글, "n": 1, "text": "[자리 못 찾음] " + 글}`로 두 번째 호출에서 단다(그래도 실패하면 결과에 남겨 알림).
- `bridge.add_memos(src, dst, memos) -> tuple[int, list[dict]]` (단 수, 못 단 메모).
- anchor·n 정하기: 엔진이 붙일 단위의 글에서 앞 40자 이내 고유한 부분을 anchor로 고르고(문서 전체 글에서 그 단위까지 나온 횟수 = n), 단위가 비었거나 글이 없으면 앞 단위 글을 쓴다. 찾기는 한글 찾기(표 안 글 포함, 문서 순서)와 같은 순서로 센다.

## 6. 명령

### `compare <옛판> <새판> [--memo <결과.hwpx>] [--json]`

- 글: 장(where)별로 `+ 추가: …`, `- 삭제: …`, `~ 수정: 원래 … → 새 …`. 바뀐 곳이 없으면 "바뀐 곳이 없어요".
- `--memo`: 새 판 사본에 바뀐 곳마다 메모. 수정·추가는 그 단위에, 삭제는 바로 뒤 단위(없으면 앞 단위)에 "[바뀜] 원래: …" / "[추가됨]" / "[삭제됨] …". 한글이 없으면 "한글이 있어야 메모를 달 수 있어요" 안내 후 목록만 출력(종료 코드 0).
- `--json`: `{"changes": [...]}`.

### `merge <원본> <의견…> <모음본.hwpx> [--accept m1,m3] [--notes 메모.json] [--json]`

1. 의견 파일마다 이름 = 파일 이름에서 원본 이름을 뺀 나머지(예: `보고서_홍길동.hwpx` → 홍길동, 겹치면 파일 이름 그대로).
2. 의견마다 번호 m1, m2…(파일 순서, 그 안에서 문서 순서):
   - 새 메모 → `{"id", "who", "kind": "memo", "text", "anchor", "where"}`.
   - 원본 대비 수정·추가·삭제(3장) → `{"id", "who", "kind": "edit"|"add"|"del", "old", "new", "where", "key"}` (key는 원본 단위 key, 추가는 바로 앞 원본 단위 key).
   - `--notes`: 따로 받은 글을 Claude가 정리한 `[{"who", "where_text": 붙일 원본 글 일부, "text"}]` → `kind: "note"`.
3. 충돌: 같은 원본 단위 key에 서로 다른 사람의 `edit`/`del`이 있고 새 글이 다르면 그 의견들에 `"conflict": [다른 id들]`.
4. 메모 글:
   - memo `[이름] 글`
   - edit `[이름 수정] 원래: … → 고친 글: …`
   - add `[이름 추가] …`
   - del `[이름 삭제 제안] …`
   - note `[이름] 글`
   - 충돌이면 앞에 `[충돌]`
5. `--accept`가 없으면: 원본 사본에 모든 의견 메모를 단 모음본을 저장(한글 필요)하고 의견 표를 출력. 한글이 없으면 표만 출력하고 "모음본은 한글이 있는 PC에서 만들어져요" 안내(종료 코드 0, 파일 만들지 않음).
6. `--accept m2,m5`:
   - 고른 `edit`는 원본의 그 단위 문단 글을 새 글로 바꾼다. 최상위 문단은 `editor.doc._set_text`와 같은 방식, 칸 문단도 같은 방식. 문단 모양과 첫 글자 모양이 유지된다.
   - `del`은 문단을 지운다(최상위·칸 모두, 칸의 마지막 문단이면 글만 비움).
   - `add`는 key 다음에 원본 그 단위 문단을 복제해 새 글을 넣는다.
   - 반영 전에 원본 단위의 글이 의견을 만들 때의 old와 같은지 확인한다. 다르면 그 의견은 건너뛰고 알린다.
   - 충돌한 의견 둘 다를 고르면 멈추고 알린다.
   - 반영하지 않은 나머지 의견은 메모로 단다(한글이 있을 때).
   - memo·note를 accept하면 "메모 의견은 반영할 글이 없어요"로 알리고 무시한다.

`--json`: `{"opinions": [...], "placed": n, "missed": [...], "applied": [...], "skipped": [...]}`.

## 7. 따로 받은 글 (스킬 안내 `reference/merge.md`)

- 대화로 받은 의견을 읽고, 의견마다 원본에서 해당 문단을 찾아 `--notes` JSON을 만든다(where_text는 그 문단의 고유한 글 일부). 확실하지 않으면 사용자에게 묻는다.
- merge 결과 표를 보여 주고 "어느 수정을 반영할까요?"를 묻는다. 충돌은 먼저 보여 준다.
- 반영 뒤 `compare 원본 결과`로 바뀐 곳을 보여 준다.

## 8. 오류 처리

| 상황 | 동작 |
|---|---|
| 의견 파일이 하나도 없음 | "의견 파일을 하나 이상 주세요" |
| 결과 파일이 원본·의견 파일과 같음 | 덮어쓰지 않음 |
| 구역이 여러 개 | 첫 구역만 비교한다고 경고(메모 읽기는 전 구역) |
| 없는 의견 번호 accept | 멈추고 있는 번호 목록 안내 |
| notes where_text를 원본에서 못 찾음 | 그 노트는 첫 본문 단위에 "[자리 못 찾음]"으로 |
| 한글 없음 | 메모 달기 대신 표만, accept 반영은 한글 없이도 함(남은 메모는 달지 못했다고 알림) |

## 9. 범위 밖

- 서식 변경 비교, 그림·수식 바뀜 비교(글만 본다).
- 한글 '변경 내용 추적' 기록 읽기.
- 표 행·열 추가/삭제의 구조 반영(칸 글만).

## 10. 시험

- compare:
  - 단위(최상위·칸, where, 빈 글 제외).
  - diff(추가·삭제·수정 ratio, 칸 수정 위치).
- memos 읽기(붙은 글, 원본 메모 제외).
- merge 의견 목록(이름, 번호, 충돌, notes, 메모 글 모양).
- accept 반영:
  - 최상위·칸 수정 서식 유지.
  - del·add.
  - 그 사이 바뀐 원본 거절.
  - 충돌 둘 다 거절.
  - 없는 번호.
- anchor·n 고르기(같은 글이 여러 번).
- CLI 글·JSON, 한글 없음 안내.
- 한글(hangul): add_memos가 메모를 실제로 달고 같은 글 둘째 자리에 붙는지, 모음본을 열면 메모 수가 맞는지.
- 수동: 원본 + 두 사람 의견 파일(메모, 직접 수정, 충돌)로 merge → 한글 쪽 그림 확인.
