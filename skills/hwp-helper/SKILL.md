# 한글(HWPX) 보고서 작성

원칙: **Claude는 내용만 쓰고, 서식은 양식(또는 프리셋)의 견본에서만 가져온다.** XML을 직접 고치지 않는다. 내용은 '보고서 마크다운'이나 '양식 지시문'으로 쓰고, 엔진이 견본을 복제해 한글 파일로 만든다.

## 0. 준비

엔진 실행 방법 (아래에서 `hwpx`라고 쓴 곳은 모두 이 명령이다):
- Claude Code 플러그인: `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py"`
- claude.ai 스킬: 이 SKILL.md가 있는 폴더의 `hwpx.py` (`python <스킬 폴더>/hwpx.py`)

처음 한 번 `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py" presets`를 실행한다.
- `No module named 'lxml'`·`'PIL'`이 나오면 "한글 파일을 다루는 데 필요한 파이썬 부품(lxml, Pillow)을 설치해도 될까요?"라고 묻고, 허락하면 `python -m pip install --user lxml Pillow`를 실행한 뒤 다시 시도한다.
- 한글(한컴오피스) 설치 여부는 `convert`·`preview`를 처음 쓸 때 결과로 안다. "한글이 설치된 Windows에서만" 오류가 나면 **기본 모드**다. 사용자에게 한 줄로 알린다: "이 환경에는 한글이 없어 미리보기와 .hwp 변환은 못 하고, 수식 크기는 추정해요."

결과는 항상 **새 파일**로 저장한다. 원본 경로를 결과로 주면 엔진이 거부한다. 결과 이름은 `<원본이름>_작성.hwpx`, 다시 고치면 `_작성2`처럼 붙인다.

## 1. 시작 질문 (AskUserQuestion, 최대 4개, 이미 말한 것은 묻지 않음)

1. 양식 파일이 있나요? → 있으면 경로(.hwp도 됨). 없으면 프리셋을 고르게 한다(`hwpx presets` 결과의 제목·설명을 선택지로). 프리셋 4종은 `reference/presets.md`.
2. 내용은 어디서? (여러 개) 대화로 설명 / 파일·폴더(분석 결과 그림·표, 기존 문서 md·docx·pdf·tex) / 이전 한글 보고서 이어쓰기
3. 결과 형식? .hwpx / .hwp / 둘 다 + PDF (기본 모드면 .hwpx만)
4. 분량? 양식·공고에 쪽수 제한이나 배점이 있으면 그것을 따르고, 없으면 묻는다: 간략(장마다 반 쪽) / 보통(장마다 1~2쪽, 기본) / 상세(장마다 3쪽 이상)

양식이 표 칸을 채우는 서식(월간보고서, 진도 보고, `progress` 프리셋)이면 **3. 양식 채우기**, 아니면 **2. 새로 쓰기**로 간다.

## 2. 새로 쓰기 (보고서·논문·공문서)

1. `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py" samples <양식 또는 프리셋 이름>`으로 견본을 확인한다. 장·절·항·글머리·본문·표·그림·수식 견본과 번호 형식이 나온다.
   - 마크다운 단계는 견본에 맞춘다. `samples`의 예시 글이 단계 안내다(예: `장 제목: 견본 '제1장 서론'` → `# 제1장 …`).
   - 본문이 글머리로 시작하는 양식이 있다. 예를 들어 최종보고서는 본문이 '· 자동 글머리' 문단이다(`· 글머리: 자동 글머리`, 본문 견본은 들여쓴 이어지는 문단). 이런 양식이면 일반 문단을 `· `로 시작해 쓴다.
   - '견본 없음'인 역할은 대신 쓸 서식이 표시된다. 꼭 필요하면 사용자에게 알린다.
2. 내용 자료를 읽는다(Read 도구로 md·docx·pdf·csv·그림, 이전 보고서는 `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py" read <파일>`).
3. **목차 초안을 보여 주고 한 번 확인받는다.** (장·절 제목, 들어갈 표·그림, 장마다 예상 분량)
   - 양식에 배점(〔15점〕)이나 '작성 요령' 상자가 있으면, 그 요령이 묻는 항목마다 답하는 절·글머리를 목차에 넣는다. 작성 요령 상자는 결과에 남기지 않는다.
4. 보고서 마크다운을 쓴다. 문법은 `reference/markdown.md`, 수식은 `reference/equations.md`.
   - 파일 쓰기 도구(Write)로 `.md` 파일에 쓴다. 역슬래시(`\frac`, `\\`)가 든 내용을 셸 heredoc으로 쓰지 않는다(역슬래시가 사라진다).
   - 긴 보고서는 장 단위로 써도 되지만, 확인할 때마다 **지금까지 쓴 장을 모두 합친 md를 원래 양식(또는 프리셋)으로 새로 렌더링**한다. 앞 장 결과 파일에 `--mode append`로 덧붙이면 그 파일에 없던 표·그림·수식·글머리 서식은 양식 서식을 잃는다(엔진이 `[주의]`로 알린다).
   - 개조식 문체(명사형 종결: "~함", "~임", "~ 추진")를 양식의 기존 글에 맞춘다.
   - **개조식은 짧은 메모가 아니다.** 한 줄에 무엇을·왜·어떻게·결과(수치)와 그 의미까지 담은 완결된 서술로, 보통 1~2줄(40~90자)을 쓴다. □ 아래 ○ 3~5개, ○ 아래 - 2~4개를 기본으로 하고, 근거 수치·비교 대상·해석("그래서 무엇을 뜻하는지")을 빠뜨리지 않는다. 단어만 나열한 줄("전처리 수행", "성능 향상")은 쓰지 않는다.
     - 나쁜 예: `- 결측값 확인`
     - 좋은 예: `- 결측값·무한값·시각 역행을 전수 점검해 0건임을 확인했으며, 따라서 보간 없이 원자료를 그대로 학습에 사용함`
   - 표·그림마다 앞뒤에 그것이 무엇을 보여 주는지, 읽는 사람이 무엇을 봐야 하는지 1~2줄로 설명한다.
   - 그림 폭: 여러 칸짜리 그래프 묶음·세로로 긴 그림은 `width=70%`~`80%`, 작은 그림은 50~60%. 미리보기에서 그림이 다음 쪽으로 넘어가 앞쪽 아래가 크게 비면, 그림 폭을 줄이거나 그림 뒤 설명 문단을 그림 앞으로 옮긴다.
   - 자료에 없는 수치·사실은 지어내지 않는다. 빈칸 `( )`으로 두고 전달할 때 목록으로 알린다.
   - 다 쓴 뒤 분량을 점검한다: 미리보기 쪽수가 1번에서 정한 분량보다 많이 모자라면 근거·해석·비교를 보강한다(같은 말 반복으로 늘리지 않는다).
5. 만든다: `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py" render <양식|프리셋> <내용.md> <결과.hwpx> --preview <미리보기 폴더>`
   - `[주의]` 줄(모르는 참조, 지원하지 않는 수식 명령 등)은 모아 두었다가 전달할 때 알린다.
   - `[오류]`로 저장하지 않았으면 원인을 고쳐 다시 한다.
   - 한글이 있으면 수식 크기를 한글이 자동으로 맞춘다.
   - 기본 모드(한글 없음)에서는 `--preview`를 붙여도 파일은 저장되고 "미리보기는 만들지 못했어요" `[주의]`만 나온다. 실패가 아니다.
6. 미리보기 폴더의 `page001.png`…를 Read 도구로 **직접 본다.** 장 제목이 쪽 끝에 홀로 남지 않는지(엔진이 '다음 문단과 함께'를 켜 둠), 큰 빈 공간이 없는지도 본다. 겹침, 이상한 줄바꿈, 빈 쪽, 표 깨짐이 없는지 확인하고 있으면 고친다.
7. 검토: `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py" review <결과.hwpx>` (자세한 뜻은 아래 6.)
   - `guide-text`(양식 안내 문구: "작성 후 삭제", "자유롭게 작성 가능", "예 시" 등)가 나오면 그 문단을 지운다: `read <결과> --anchors`로 번호를 찾고, 빈 내용 파일로 `render <결과> <빈.md> <결과2> --replace a:b`.
   - **표지·요약 칸 채우기**: 양식 첫머리에 표지 표(프로젝트명·팀명·과제명·내용요약·날짜·서명란 등)가 있고 `empty-cell`로 비어 있다고 나오면, `fields <결과>`로 칸 주소를 보고 **3. 양식 채우기** 방식(`fill`)으로 채운다. 팀명·이름·소속·날짜처럼 자료에 없는 정보는 사용자에게 묻는다(한 번에 묶어서). 내용요약 칸은 본문 각 장의 핵심 결과를 3~6줄 개조식으로 요약해 넣는다.
8. 결과 형식이 .hwp면 `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py" convert <결과.hwpx> <결과.hwp>`, PDF도 같은 방법.

## 3. 양식 채우기 (월간보고서·진도 보고·기관 서식)

1. `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py" fields <양식>`으로 칸 목록과 칸마다 쓸 주소(`@칸 표3 | 추진 과제 1 | 금월 추진실적`)를 본다. 주소는 그대로 복사해 쓴다.
2. 지시문을 쓴다(문법·주의는 `reference/form.md`):
   - `@바꾸기 옛 글자 => 새 글자` — 표지·보고일·달 머리(`(26. 02.)`) 같은 글자. 달을 바꿀 때는 **뒤 달부터** 바꾼다(`(26. 03.)→(26. 04.)`를 먼저, 그다음 `(26. 02.)→(26. 03.)`).
   - `@칸 표N | 행 머리 | 열 머리` 다음 줄부터 칸 내용(□ ○ - · 글머리, 일반 글, `$수식$`). 행·열 번호로 쓸 때는 `#2`처럼 `#`을 붙인다.
   - `@행수 표N | 전체 행 수` — 별첨처럼 줄 수가 달마다 바뀌는 표.
3. **채울 내용 요약을 보여 주고 한 번 확인받는다.**
4. `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py" fill <양식> <지시문.md> <결과.hwpx> --preview <폴더>`
   - 칸의 글머리·글자색·빈 줄 간격과 칸에 붙은 메모는 엔진이 지킨다. 메모를 옮겨 붙였다는 `[주의]`는 사용자에게 알린다.
   - `n번째 줄: …` 오류는 그 줄을 고쳐 다시 한다. "여러 칸이 맞아요"면 후보 중 맞는 머리를 정확히 쓰거나 `#번호`로 쓴다.
5. 미리보기 확인 → `review` → 전달.

## 4. 일부만 고치기

1. `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py" read <파일> --anchors`로 읽는다. 문단마다 `<!-- @n -->` 번호가 붙는다.
2. 바꿀 범위 `a`(첫 문단 번호)부터 `b`(바꿀 마지막 문단 다음 번호)를 정하고 새 내용을 마크다운으로 쓴다.
3. `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py" render <파일> <새내용.md> <결과.hwpx> --replace a:b --preview <폴더>`
   - 표 제목(`표:` 줄)과 표는 앵커가 따로 붙는다. 표를 바꿀 때는 제목 문단까지 범위에 넣는다.
4. 번호가 어긋났으면 `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py" renumber <결과.hwpx> <결과2.hwpx>`.

## 5. 변환·수식 크기

- `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py" convert <원본> <결과.hwp|.hwpx|.pdf>` (한글 필요)
- `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py" equations <파일.hwpx> <결과.hwpx>` — 한글 없는 곳에서 만든 문서의 수식 크기를 한글로 맞춘다.
- `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py" preview <파일> <폴더>` — 쪽 이미지
- `python "${CLAUDE_PLUGIN_ROOT}/hwpx.py" validate <파일>` — 한글에서 깨질 만한 곳 검사

## 6. 검토 결과 읽기

`review`의 `[오류]`(요일 불일치, 없는 날짜, 없는 표·그림 참조, 번호 중복)는 고칠 것을 제안하고, `[확인]`(보고일 연도, 달 머리, 번호 건너뜀, 안내 문구 잔존, 빈 칸, 글꼴·서식 혼용)은 사용자에게 확인을 요청한다. 날짜·숫자처럼 사실이 걸린 것은 Claude가 임의로 바꾸지 않고 묻는다.

## 6-1. 열린 한글 창에서 바로 고치기

사용자가 "한글에서 고른 부분", "지금 열어 둔 문서", "커서 있는 데"처럼 열린 한글 창을 말하면 파일 대신 `live` 명령을 쓴다. 절차와 주의는 `reference/live.md`.

사용자가 "앱에서 보면서 고칠래", "화면에 띄워서 고치자"처럼 Claude 앱 안에서 문서를 보며 고치려 하면 `edit` 명령을 쓴다. 원본은 그대로 두고 사본을 고친다. 절차는 `reference/editor.md`.

## 7. 전달

- 결과 파일 경로(마크다운 링크), 미리보기 1~2쪽(가능하면), "확인 필요" 목록(`[주의]`, `review` 결과, 출처 없는 수치)을 짧게 정리한다.
- 기본 모드면: "한글이 없어 미리보기 없이 구조 검증만 했어요. 수식 크기는 추정값이니 한글에서 열어 확인해 주세요. 한글이 있는 PC에서 `equations` 명령으로 정확히 맞출 수 있어요."
- 한글 외 뷰어(한컴독스 등)에서는 줄 배치가 조금 다를 수 있다고 필요할 때 알린다.

문제가 생기면 `reference/troubleshooting.md`를 본다.
